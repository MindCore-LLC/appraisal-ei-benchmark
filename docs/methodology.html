Methodology v1.0.0

How the Appraisal-EI Benchmark works, end to end - no code reading required.

What it measures

Most emotion evaluations ask what a person feels. This benchmark asks whether a model represents why - the causal structure appraisal theory says produces the emotion. Every stimulus is scored as a 17-dimensional appraisal vector (each dimension -3.0 to +3.0), not an emotion label. A model's answer is compared to human gold ratings dimension-by-dimension.

The dimensions come from appraisal theory (Smith & Ellsworth, Scherer's CPM, OCC): pleasantness, goal relevance, goal congruence, certainty, control, responsibility, fairness, effort, expectation, novelty, urgency, intensity, coping potential, social desirability, moral worth, attribution, and anticipated emotion.

Keyword-free matters: vignettes contain no emotion words. "After eight years at the firm, Sam was told the role would end in thirty days" - the model must infer the appraisal structure, not pattern-match a sentiment lexicon. The 350 items span 20 situation families (job loss, betrayal, inheritance, public error...).

Audio stimuli are references, not files: wav_ref paths map to a standard RAVDESS download (research-licensed, not redistributed). The same 17 dims are rated on vocal delivery, not transcripts.

The protocol, step by step

  1. Prompt. Each test item is sent zero-shot with the canonical rubric: the 17 dimension definitions, the scale, the scenario, and "Return JSON only, keys exactly those 17 names."
  2. Parse. The first {...} JSON object in the response is extracted. A response counts as parsed only if it yields ≥8 of the 17 dimensions.
  3. Score per item. Per-item score = Pearson correlation between the model's 17-dim vector and the gold vector for that item. r captures profile shape - which dimensions are extreme vs neutral - not just magnitude matching.
  4. Aggregate. Headline appraisal calibration = mean per-item r across the test split. Per-dimension calibration = Pearson r of predicted-vs-gold on each single dimension across all items (the radar chart on the leaderboard).
  5. Record. Everything lands in results/<model>.json: the score, the per-item r values, the per-dim stats, the raw predictions, the gold source, the timestamp, and the status.
Same prompt, every model. The rubric is fixed by SPEC, not tuned per model. Zero-shot (no examples) keeps the test about the model's representation, not prompt engineering.

Status badges - read these first

BadgeMeans
smokeScored against generator priors - plausible ratings written by the vignette generator, not humans. Provisional by definition.
measuredScored against human gold - real annotator ratings meeting the κ>0.6 agreement bar.

Gold provenance is declared per stimulus directory in gold_status.json - a versioned statement, not guessed from the data. Today's v1.0.0 stimuli are generator priors, so every current row is SMOKE. Human gold (Prolific annotation, ≥2 annotators/item) lands in v1.1 and results re-badge automatically.

The leaderboard pipeline

  • scoring/run_eval.py - the runner. One command per model; supports OpenAI, Together, Fireworks (any OpenAI-compatible endpoint). Writes a result JSON.
  • models.json - the registry the filters read: display name, org, origin (ISO country of the publishing org), open/closed weights, family, params.
  • site/build_site.py - merges results + registry into docs/data.json, the single payload this site fetches.
  • docs/index.html - the leaderboard: sortable columns, origin/weights/org chips, checkbox compare, per-item sparklines, the bar chart and 17-axis radar.

Adding a model

# 1. registry entry in models.json (name, org, origin, weights)
# 2. run it:
python scoring/run_eval.py --provider together \
    --model org/model-id --name "Display Name"
# 3. rebuild the site payload and push:
python site/build_site.py && git add -A && git commit -m "add X" && git push

Compare links are shareable: ?compare=all or ?compare=gpt-5.4,deepseek-ai/DeepSeek-V4-Pro-0813.

Auditing a score

Every leaderboard number is reproducible from the repo alone:

  • results/<model>.json → per_item has every item's r, prediction, and gold vector
  • per_dim has per-dimension r + mean absolute error
  • scoring/score.py is the reference implementation of every metric (numpy+scipy only)
  • The prompt text is generated deterministically from schema/rating_schema.json
Honest caveat: a model's vignette text is public, so frontier training corpora may contain it. This is the standard public-benchmark contamination tradeoff - mitigated by keyword-free stimuli, private gold labels (planned), and versioned releases. Report anything that looks gamed.

Versioning

VERSION + git tags pin the artifact; the leaderboard and all results record which version scored them. Stimuli are append-only within a major version - corrections bump minor (1.0→1.1), schema changes bump major (2.0). Full rules and the sub-score definitions are in SPEC.md - the normative document.
